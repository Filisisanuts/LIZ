## 四、配置系统

### 4.1 配置存储

配置存储在 `localStorage`，键名格式：`ax_app_config_{用户ID}`

```typescript
interface AppConfig {
  enabledModules: string[];        // 启用的模块
  dailyLabels: string[];           // 日报标签
  dailyFeatures: {
    roomEnabled: boolean;          // 包厢预定
    reporterEnabled: boolean;      // 汇报人
  };
  purchaseSections: string[];      // 采购区域
  purchaseSources: string[];       // 采购来源
  purchaseCategories: Record<string, string[]>;  // 区域-分类
  expenseCategories: string[];     // 费用分类
  warehouseCategories: string[];   // 仓库分类
  inventoryTypes: string[];        // 贵重物品类型
  customInventoryTypes: string[];  // 自定义贵重物品
  onboardingCompleted: boolean;    // 引导完成状态
}
```

### 4.2 配置读取

```javascript
// 读取当前用户配置
function getAppConfig() {
  const key = getConfigKey();
  const saved = localStorage.getItem(key);
  return saved ? JSON.parse(saved) : null;
}

// 获取配置键（包含用户ID）
function getConfigKey() {
  if (_auth?.loggedIn && _auth?.user?.id) {
    return `ax_app_config_${_auth.user.id}`;
  }
  return 'ax_app_config';
}
```

### 4.3 兼容性

- **新用户**：通过引导配置，`enabledModules` 有值
- **现有用户**：无配置，`enabledModules` 为空或不存在
- **判断逻辑**：无配置或配置为空时显示所有模块

## 五、模块开发规范


### 5.2 服务层规范

```typescript
// {module}-service.ts

import legacyBridge from '@/legacy/legacy-bridge';

// 类型定义
export interface Item {
  id: string;
  // ...
}

// 数据获取
export function getItems(): Item[] {
  const db = legacyBridge.getDatabase();
  return db?.items || [];
}

// 数据操作
export function createItem(item: Omit<Item, 'id'>): Item {
  const newItem = { id: `item_${Date.now()}`, ...item };
  legacyBridge.update((db) => {
    db.items.push(newItem);
  });
  return newItem;
}
```

## 六、编码规范

### 6.1 TypeScript

- 新代码必须使用 TypeScript
- 为所有函数参数和返回值添加类型
- 使用 `interface` 定义复杂类型

### 6.2 JavaScript（旧系统）

- 使用 `var` 声明变量（兼容旧系统）
- 函数声明使用 `function` 关键字
- 避免使用 ES6+ 箭头函数（兼容性）

### 6.3 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 文件名 | kebab-case | `dashboard-service.ts` |
| 函数名 | camelCase | `getItems()` |
| 类型名 | PascalCase | `AppConfig` |
| 常量 | UPPER_SNAKE_CASE | `CONFIG_KEY` |
| CSS 类名 | kebab-case | `.stat-card` |

### 6.4 注释规范

- 函数必须添加 JSDoc 注释
- 复杂逻辑添加行内注释
- TODO 使用 `// TODO:` 格式

## 九、统一配置读取与迁移

所有旧 JavaScript、TypeScript 模块和新手引导页必须通过统一配置存储层读取或保存 AppConfig，禁止直接读取 ax_app_config 或重复实现 getAppConfig()。

- 配置来源按当前用户本地配置、云端 DB.settings、早期公共配置、旧业务数据的顺序兼容读取。
- 迁移按字段补齐；onboardingCompleted 不再作为跳过迁移的条件。
- schemaVersion >= 2 后，用户明确清空的空列表保持为空，不从旧数据重新填充。
- 保存配置时同时写入当前用户键、DB.settings 并触发云同步。
- “新用户/旧用户”只用于理解历史数据来源，不作为页面功能分支；只有无配置且无业务数据的账号进入新手引导。

## 十、静态资源缓存与发布验收

旧系统脚本和样式通过普通 script、link 标签加载。Vite 构建时根据 src/js/*.js、src/css/style.css 的内容生成版本号，并重写入口 HTML 中的资源 URL。

- 修改旧系统 JS/CSS 后必须重新构建，不能依赖手工修改 ?v=。
- 发布后使用正常浏览器检查 Network 中实际加载的资源 URL 和内容；无痕窗口只能用于辅助定位缓存问题。
- 构建成功、HTTP 200、服务器文件哈希一致都不能单独作为浏览器已加载新版本的证明。
- 普通浏览器与无痕浏览器行为不同时，同时检查 HTTP 缓存和 localStorage、云端配置。
