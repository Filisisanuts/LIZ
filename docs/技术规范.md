### 图标系统

- 功能图标的 SVG 路径只定义在 `src/js/icon-registry.js`；旧 JavaScript 使用全局 `axIcon(name)`，TypeScript 通过 `src/shared/ui/icon-bridge.ts` 调用同一字典。
- 图标的线宽、尺寸、导航与状态用法统一放在 `src/styles/components/icons.css`，业务页面不得重复定义 SVG 路径或以 Emoji 作为功能图标。

## 四、配置系统

### 4.1 配置存储

配置存储在 `localStorage`，键名格式：`ax_app_config_{用户ID}`

```typescript
interface AppConfig {
  enabledModules: string[];        // 启用的模块
  dailyLabels: string[];           // 日报标签
  dailyFeatures: {
    roomEnabled: boolean;          // 包厢预定
    reporterEnabled: boolean;      // 汇报人
  };
  purchaseSections: string[];      // 采购区域
  purchaseSources: string[];       // 采购来源
  purchaseCategories: Record<string, string[]>;  // 区域-分类
  expenseCategories: string[];     // 费用分类
  warehouseCategories: string[];   // 仓库分类
  inventoryTypes: string[];        // 贵重物品类型
  customInventoryTypes: string[];  // 自定义贵重物品
  inventoryTypeDefinitions: InventoryTypeDefinition[]; // 账号库存类型与操作配置
  onboardingCompleted: boolean;    // 引导完成状态
}

interface InventoryTypeDefinition {
  id: string;
  name: string;
  preset: 'tea' | 'cig' | 'alc' | 'other' | 'other-category' | 'generic';
  legacyCategory: string;
  archived: boolean;
  deleted: boolean;
  dailyLink: boolean;
  actions: { add: boolean; inbound: boolean; sale: boolean; adjust: boolean; loss: boolean };
}
```

`inventoryTypeDefinitions` 以稳定 ID 保存类型名称、流程预设、归档/删除状态、可用操作和日报联动开关。旧 `inventoryTypes`、`customInventoryTypes` 及旧贵重物品分类在读取时迁移为类型定义；旧固定库存仍使用原业务数据和专属流程。

### 4.2 配置读取

```javascript
// 读取当前用户配置
function getAppConfig() {
  const key = getConfigKey();
  const saved = localStorage.getItem(key);
  return saved ? JSON.parse(saved) : null;
}

// 获取配置键（包含用户ID）
function getConfigKey() {
  if (_auth?.loggedIn && _auth?.user?.id) {
    return `ax_app_config_${_auth.user.id}`;
  }
  return 'ax_app_config';
}
```

### 4.3 兼容性

- **新用户**：通过引导配置，`enabledModules` 有值
- **现有用户**：无配置，`enabledModules` 为空或不存在
- **判断逻辑**：无配置或配置为空时显示所有模块

```typescript
// {module}-service.ts

import legacyBridge from '@/legacy/legacy-bridge';

// 类型定义
export interface Item {
  id: string;
  // ...
}

// 数据获取
export function getItems(): Item[] {
  const db = legacyBridge.getDatabase();
  return db?.items || [];
}

// 数据操作
export function createItem(item: Omit<Item, 'id'>): Item {
  const newItem = { id: `item_${Date.now()}`, ...item };
  legacyBridge.update((db) => {
    db.items.push(newItem);
  });
  return newItem;
}
```

## 九、统一配置读取与迁移

所有旧 JavaScript、TypeScript 模块和新手引导页必须通过统一配置存储层读取或保存 AppConfig，禁止直接读取 ax_app_config 或重复实现 getAppConfig()。

- 配置来源按当前用户本地配置、云端 DB.settings、早期公共配置、旧业务数据的顺序兼容读取。
- 迁移按字段补齐；onboardingCompleted 不再作为跳过迁移的条件。
- schemaVersion >= 2 后，用户明确清空的空列表保持为空，不从旧数据重新填充。
- 保存配置时同时写入当前用户键、DB.settings 并触发云同步。
- “新用户/旧用户”只用于理解历史数据来源，不作为页面功能分支；只有无配置且无业务数据的账号进入新手引导。

## 十、静态资源缓存与发布验收

旧系统脚本和样式通过普通 script、link 标签加载。Vite 构建时根据 src/js/*.js、src/css/style.css 的内容生成版本号，并重写入口 HTML 中的资源 URL。

- 修改旧系统 JS/CSS 后必须重新构建，不能依赖手工修改 ?v=。
- 发布后使用正常浏览器检查 Network 中实际加载的资源 URL 和内容；无痕窗口只能用于辅助定位缓存问题。
- 构建成功、HTTP 200、服务器文件哈希一致都不能单独作为浏览器已加载新版本的证明。
- 普通浏览器与无痕浏览器行为不同时，同时检查 HTTP 缓存和 localStorage、云端配置。

## 十一、采购 AI 识别边界

- 历史商品只按规范化品名匹配：优先精确命中；OCR 名称与唯一历史品名仅差一个字符时才自动采用。命中后用最近一笔非退货采购记录中的名称替换识别名称，并取该记录的区域和分类。
- 最近记录按采购日期确定；同日或日期缺失时，以采购数组中顺序靠后的记录为准。最近记录中的区域/分类只在仍存在于当前账号配置时自动回填；缺失或已失效时提示核对。更早记录与最近记录不一致时，仍以最近记录为准。品名候选不唯一时不应用名称或分类；匹配成功、OCR错字纠正及待核对原因都在对应物品行显示简短提示。识图结果保留逐项区域/分类，单张采购单允许包含多个区域；区域和分类仍可逐项编辑，批量填充作为可选操作。
- AI 返回的区域和分类仅作识图候选，不绕过历史匹配或当前账号配置直接写入。未匹配物品由用户核对名称、区域和分类。
- AI 识别到的来源先统一空白，再与当前账号已配置来源做精确匹配或唯一、具体的简称匹配。未匹配、存在歧义或过于通用的来源必须由用户从已配置来源中选择；识图流程不添加临时来源、不回退到首项，也不能把未配置来源保存进采购单。
- 采购单顶部来源是整单权威值，用户变更后同步所有明细行。编辑历史采购时可保留其原来源；来源选择、设置、详情、退货、搜索、报表和汇报等动态显示必须转义 HTML，内联事件不得拼入用户来源文本。
- MiMo 模型列表由设置页按 API 地址请求兼容的 `/models` 接口；当前已保存模型和手工输入始终可用，模型列表接口失败不能阻塞图片识别。模型列表不代表视觉能力保证。

## 十二、采购退货明细关联

退货明细优先使用原采购明细 ID 关联剩余可退数量。旧采购数据缺少明细 ID 时，回退键必须使用“原采购单 ID + 该明细在原采购单中的数组索引”，并与剩余数量统计逻辑使用同一规则；不得使用当前退货单或筛选后列表中的行索引。

待修正历史退货在列表中按当前记录对象定位，并在写入前再次核对记录仍处于待修正状态；关联成功时才为缺失或重复编号的退货补发唯一编号。单条删除将原记录快照和数组位置放入采购回收站，保留 30 天并可恢复。关联原采购选择器支持选择年月和前后月浏览，默认当前月；切换月份时保留品名搜索，只有包含匹配正数原采购明细的日期可选。

## 十三、旧库存月度期初与盘存结存

- 旧茗茶、香烟、酒及贵重物品库存按月份分别记录 `monthOpeningStock`（月初期初）与 `monthClosingStock`（月底盘存结存）；当月期初来自独立月度快照，不从当前 `openingStock` 回退填充历史月份。
- 月初结转继续由现有弹窗逐类呈现，用户核对或修正盘存数后确认；确认值保存为上月结存及本月期初。跳过时，仅在已有上月结存可用时带入；否则将本月期初标记为未记录。
- 月度库存优先使用明确的结存快照，否则使用该月期初及当月流水计算。缺少期初时显示“期初未记录”，不得按零库存参与补货告警、销售/退货等库存扣减操作。
- 旧 `monthStock` 的历史含义不明确，保留原值，不批量猜测或迁移；缺少新月度期初快照的历史月份需人工补录。该兼容策略不适用于自定义库存类型。

## 十四、账号自定义库存与视口表格

- 生产发布记录：2026-10-12 应用提交 `f0a80f9` 与文档提交 `b88a582` 已推送至 `main` 并发布到 `/srv/ax-coffee`；备份为 `/srv/ax-coffee.backup-before-f0a80f9`。本地构建、`nginx -t` 和重载通过，`nginx`、`cloudflared-coffee` 均 active；公网首页与主要库存脚本/样式 HTTP 200，版本化库存脚本在当前浏览器实际加载，公网文件 SHA256 与本地构建一致。真实云同步、保存重开、窄屏视觉和触屏拖动尚未验收。

- 类型配置由账号级 `inventoryTypeDefinitions` 管理；隐藏仅用于分组的“贵重物品”汇总入口。旧分类映射为独立类型，无法映射的旧商品通过“未分类”入口查看。归档隐藏侧边栏入口但保留类型与流水；有商品或历史的类型不能删除。
- 新类型商品保存在 `DB.inventoryCustomItems`，通过现有整库 `cafe_data` 用户数据路径同步，无新增 Supabase 表。商品有自己的计量单位、期初库存/单价、售价和补货提醒；存在流水后锁定单位，避免历史数量换算含义改变。
- 通用流水由 `inventoryLedger` 按业务日期、创建顺序和 ID 排序，逐商品按 FIFO 扣减批次成本。销售超出可用成本批次时保留负库存并提示未结转数量；补录日期早于销售的入库会重新计算后续成本，销售日期之后的入库不回填旧销售成本。
- 类型可分别配置添加、入库、销售、盘点调整、报损及日报联动。关闭操作阻止新增记录但不抹除历史；日报联动销售只在“库存销售”区域展示，不并入总流水或实收。
- 贵重物品、通用库存及仓库分类的目标表格使用 `.tw-viewport-scroll`，将横纵滚动限制在表格视口；库存页面再按内容实际位置缩小可用高度，避免多余整页空白。
- 工资字段布局编辑器中，字段名列按组内最长字段名自适应，分组标题不参与测量；窄屏将字段名列固定并让其余列横向滚动。拖动手柄未发生实际移动时不改变位置；新增工资组/工资字段/信息字段后滚到新项。公式引用与计算归属继续独立于展示位置。
