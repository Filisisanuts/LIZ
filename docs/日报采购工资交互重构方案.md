# 日报、采购、工资交互重构方案

## 一、目标

统一高频业务页的视图切换和控件语言，降低用户在录入、查看明细、退货、模板维护之间的理解成本。

本方案只定义交互、数据兼容和组件边界，不直接修改正式业务代码。

## 二、整体交互原则

- 主视图切换统一使用分段按钮：日报为“录入 / 明细”，采购为“录入 / 退货 / 明细”，工资为“录入 / 明细”。
- 粘贴文本框属于录入入口，不再单独占一个主标签。
- 解析后的结果直接落入可编辑的结构化录入区，解析前后的数据状态必须可区分。
- 退货是业务动作，不是供应商来源；退货记录必须继承原采购的来源、区域和分类。
- 表单控件统一使用可复用下拉框、日期选择器和主题变量。
- 所有主要操作保留键盘路径、焦点反馈、错误反馈和 44px 触控目标。

## 三、日报页

### 3.1 页面结构

1. 顶部标题栏
2. 录入 / 明细分段按钮
3. 录入态：文本框 + 解析按钮
4. 解析成功后：结构化经营数据编辑区
5. 明细态：按日期筛选的历史日报列表

### 3.2 状态模型

- idle：尚未解析
- parsing：正在解析
- parsed：已有结构化草稿，尚未保存
- saving：保存中
- saved：已保存并进入明细

解析结果保留草稿状态，用户可以修改任何字段后再保存。

### 3.3 兼容策略

- 保留现有日报数据结构，不重写历史记录。
- 解析逻辑输出当前日报表单使用的同一份字段结构。
- 日报自定义标签继续从统一配置读取。

## 四、采购页

### 4.1 页面结构

顶部固定保留粘贴分析文本框。

主分段按钮：

- 录入：新建正常采购单
- 退货：选择原采购并创建退货记录
- 明细：查看采购、退货和价格趋势

### 4.2 录入态

录入区直接显示现有手动字段：

- 日期
- 来源
- 物品名称、数量、单位、单价、总价
- 区域
- 分类

来源配置不再包含“退货”。

### 4.3 退货态

退货流程采用两步：

1. 选择原采购单或原物品
2. 填写退货日期、数量、金额和可选原因

退货记录应保存：

- originalPurchaseId
- originalItemId
- originalSource
- originalSection
- originalCategory
- returnDate
- returnQty
- returnTotal
- returnReason

现有历史数据中的 source = 退货记录需要迁移为上述结构；迁移后仍保留旧 source 字段作为兼容读取字段。

### 4.4 明细态

- 正常采购和退货分开展示。
- 退货金额使用负数或独立退货列展示。
- 区域、分类、来源统计使用原始归属，不把退货重新归类到供应商“退货”。

## 五、工资页

### 5.1 页面结构

录入 / 明细分段按钮保持不变，录入态按部门分组：

- 部门标题
- 部门员工行
- 部门合计行
- 全部部门总计行

### 5.2 部门模型

建议增加部门配置：

- salaryDepartments: string[]

员工行继续保存 department 字段，部门合计由员工行实时计算，不单独存一份容易过期的合计数据。

### 5.3 模板模型

跨浏览器保存的模板放入统一账号配置，并通过云端同步：

- salaryTemplate: Array<{
  department: string,
  employee: string,
  position: string,
  baseSalary: number
}>

模板只保存姓名、职务、基本工资和部门。津贴、提成、社保、个税、备注等字段不进入模板。

加载模板时只创建这四项，其余工资字段保持为空或 0。

### 5.4 兼容策略

- 首次读取时兼容 getConfigKey() + _salaryTemplate 旧 localStorage。
- 旧模板转换为新模板结构并写入统一配置。
- 跨浏览器验证必须覆盖新设备首次登录、云端配置恢复和本地模板升级。

## 六、可复用下拉框

组件需要提供：

- options
- value
- placeholder
- disabled
- searchable（可选）
- onChange
- onFocus / onBlur
- error / helperText
- size

视觉和行为要求：

- 使用主题变量，不把颜色写死。
- 支持鼠标、触摸和键盘。
- 支持 Tab、方向键、Enter、Escape。
- 焦点状态清晰，菜单打开时不遮挡当前输入。
- 支持长选项截断和移动端滚动。
- 与日期选择器共用圆角、边框、阴影和焦点变量。

## 七、验证范围

- 日报：解析、修改、保存、刷新、明细查看。
- 采购：正常录入、退货继承归属、历史退货迁移、明细统计。
- 工资：部门合计、模板保存、跨浏览器恢复、旧模板迁移。
- 组件：浅色/深色主题、键盘、焦点、禁用、错误态、移动端触控。
- UI：1440、1024、768、375 宽度，无横向溢出，焦点不被弹窗遮挡。

## 八、已确认决策

- 日报未匹配字段进入待确认区，可映射或删除，全部处理完才能保存。
- 日报再次解析时弹出“合并 / 覆盖”；合并冲突按字段选择。
- 日报只保存最终数据，不保存原文和字段映射中间状态。
- 采购允许跨日期、多次部分退货，累计数量不能超过原采购数量。
- 退货金额默认按原采购单价计算，可修改；无单价时必须手动填写。
- 退货按负数计入原来源、区域、分类，并保留退货类型标识。
- 历史退货唯一匹配自动迁移，歧义进入待修正退货。
- 修改原采购同步退货归属；删除原采购和关联退货进入 30 天回收站。
- 工资部门支持新增、重命名、排序、停用；删除部门后员工进入未分部门。
- 工资行保存隐藏员工 ID；模板保存部门、姓名、职务、基本工资。
- 模板支持多个命名模板、默认模板自动载入、载入合并、重命名、删除和导出 Excel。
- 部门小计默认逐列汇总所有金额项目。
- 下拉框支持单选、多选、搜索和自定义选项；自定义选项随表单保存。
- 下拉框选项超过 10 个启用搜索；移动端复杂选择使用底部面板，简单单选保留原生控件。
- 日报只保留一份解析/手动草稿表单；解析和手工输入都在同一份金额表单中完成。
- 日报核心经营字段和分组可在设置中完全自定义，字段可配置名称、分组、顺序、显示和统计归属。
- 删除字段只隐藏录入项，历史日报和报表继续读取原值；配置随账号云端保存。
- 日报贵重物品填写项排在营收、支付、应收、外卖、客情、包厢预定之后。

## 九、实施状态

- 通用控件、日报、采购、工资和 UI 修复已实现。
- Playwright 覆盖日报解析、采购退货/回收站、工资模板/部门小计、下拉框和移动端布局。
- 仍保留历史模块的 emoji 图标和部分旧式点击容器，但共享增强层已补可访问名称和键盘操作。
